## 3. 内部接口与数据模型

### 3.1 游戏核心接口

`GameCore` 以可注入配置构造，默认值集中在 `game-core.js`：

```js
new GameCore({
  cols: 20, rows: 20,
  initialSnake, initialFood, random,
  initialStepMs: 150, speedUpMs: 6, minStepMs: 70,
  foodPoints: 10,
})
```

- 只读状态：`state`、`snake`、`direction`、`food`、`score`、`stepMs`。
- `start()`：从 `idle` 进入 `running`，保留构造时的初始棋盘。
- `turn(dx, dy)`：仅 `running` 接受；合法时写入单槽待转方向，返回是否接受。
- `step()`：仅 `running` 执行一个逻辑步，返回 `moved | ate | gameover | ignored`。
- `pause()` / `resume()`：只在对应状态生效。
- `restart()`：重建初始蛇、食物、得分、方向和 150ms 步长，并直接进入 `running`。

蛇使用头在前的坐标数组，初始为 `(10,10)`、`(9,10)`、`(8,10)`，方向 `(1,0)`。测试可传入固定蛇、食物和随机函数，不需要 DOM、计时器或真实等待。

纯函数 `classifyRecord(score, bestAtRoundStart)` 返回四种结算文案之一；`createBestScoreStore(storage)` 封装 localStorage 读写与异常降级，便于 UI 使用。

### 3.2 根状态与 UI 状态

| 状态 | 棋盘/计时 | 可用输入 | 主要界面 |
| --- | --- | --- | --- |
| `idle` | 初始棋盘，不启动 rAF | 开始按钮、开始快捷键 | 标题、玩法说明、最高分、开始按钮 |
| `running` | 每个逻辑步推进一格 | 方向键/WASD、四向按钮、暂停 | 棋盘、得分、最高分、暂停按钮 |
| `paused` | 停止 rAF 与累积，清空旧时间 | P/Esc、暂停按钮的继续动作 | 棋盘背景、暂停提示、继续按钮 |
| `gameover` | 停止推进，保留终局棋盘 | 再来一局 | 终局分数、最高分、纪录文案、再来一局 |

所有状态切换由同一 `app.js` 控制函数完成，再统一刷新 DOM、Canvas、按钮禁用态和焦点，避免多个事件各改一半状态。

## 4. 核心规则与计时

### 4.1 单个逻辑步

1. 若存在待转方向，先消费它并清空；不存在则沿当前方向。
2. 计算下一蛇头坐标；越出 20×20 立即 `gameover`，得分不变。
3. 判断是否吃到食物。未进食时尾部将在本步移走，因此自撞检测排除当前尾格；进食时尾部保留，按完整蛇身检测。撞到非尾格立即 `gameover`。
4. 未进食：插入新头并删除尾；进食：插入新头、`score += 10`、`stepMs = max(70, stepMs - 6)`，并从全部空格中均匀选择一个新食物。
5. 食物候选由「棋盘全部坐标减蛇身」生成后一次抽取，不使用可能耗尽循环的随机重试；食物保证不与蛇重叠。

### 4.2 输入规则

- 方向键与 WASD 映射为四个单位向量；同方向按键为空操作。
- 候选方向若与当前方向完全相反，立即拒绝且不写入队列，因此不会在下一步反噬。
- 其他合法方向写入唯一待转槽，替换本步内更早的待转值；每个逻辑步最多消费一次，从而阻止快速连按形成回环。
- 仅 `running` 接受转向；`idle`、`paused`、`gameover` 中的转向输入不缓存。
- 方向键处理时 `preventDefault()`，避免页面滚动；焦点位于原生按钮等交互元素时不劫持 Enter/空格。

### 4.3 固定步长、渲染与暂停

- rAF 只负责采样时间并画帧；逻辑速度由 `stepMs` 决定。
- 每帧 `elapsed = now - lastFrame`，accumulator 增加 elapsed；达到 `stepMs` 时只执行一次 `step()`，再减去一个 `stepMs` 以保留少量帧余量；若扣除后仍大于等于一个步长则丢弃该积压。单帧不补多步，跨帧也不追赶。
- `start()`、`resume()` 后重置 `lastFrame` 与 accumulator，第一步等待完整的当前步长；首次棋盘立即绘制。
- 暂停、自动暂停和切回前台都不累积后台时间；不自动继续，用户主动继续后重新等待完整步长。
- `visibilitychange` 在页面隐藏且状态为 `running` 时调用 `pause()`；回到前台保持 `paused`。
- 加速只改变下一个逻辑步的间隔，不修改当前已在执行的一步。

### 4.4 最高分与结算

- 存储键为 `snake-h5.best-score`，内容为十进制非负整数；读取时捕获访问异常、解析失败和非法值，统一回退到 0。
- 写入使用 `try/catch`；失败时仍保留本次会话的内存最高分，游戏不受影响，不显示虚假的持久化保证。
- 每次开始或再来一局时记录 `bestAtRoundStart = best`。只在首次进入 `gameover` 时比较并更新：`score > bestAtRoundStart` 则更新内存并尝试持久化。
- 结算文案严格为：新纪录 `新纪录！`；正分同分 `追平最高分（未破纪录）`；低分 `未破纪录`；首次 0/0 `未破纪录`。
- 结算层始终显示本局得分、结算后的最高分、「再来一局」按钮。

## 5. 页面、交互、可访问性与响应式

### 5.1 页面结构

- 页头显示游戏名、当前得分、最高分与暂停/继续按钮。
- 主区域包含一个有 `aria-label` 的 Canvas 棋盘和状态文本；覆盖层承载首屏、暂停与结算内容。
- 四向按钮使用原生 `<button>`，十字布局，单键最小 `56×56px`，标注方向与 `aria-label`。
- 所有颜色使用本地 CSS 变量；深色底 `#0b1220`、正文 `#f8fafc`、次级文字 `#cbd5e1`、主按钮深绿底白字，蛇与食物使用高亮但非唯一信息载体。实现后用对比度检查确认正文 ≥ 4.5:1。

### 5.2 键盘与焦点

- `idle` 中仅当焦点在开始按钮或非交互区域时，Enter/空格开始；焦点在其他按钮时保留其原生行为。
- 开始后焦点移到 `tabindex="0"` 的棋盘区域，避免停留在已隐藏的开始按钮。
- P/Esc 在 `running` 与 `paused` 间切换；键盘可走完开始、转向、暂停、继续、结算、再来一局闭环。
- 暂停层出现时焦点进入「继续」，结算层出现时进入「再来一局」；覆盖层下的棋盘与四向按钮使用 `hidden`/`inert`（有兼容降级）隔离，关闭后恢复。
- 所有按钮有可见的 `:focus-visible` 轮廓；不使用只有颜色变化而无轮廓的焦点样式。

### 5.3 读屏与动态状态

- 分数区使用 `aria-live="polite"`，分数或最高分变化时更新简洁文本，例如「得分 10，最高分 30」。
- 暂停和结算层使用 `role="dialog"`、`aria-modal="true"` 与已关联标题；结算结果另由 live region 宣告。
- Canvas 提供简短可读描述；按钮均有文本或 `aria-label`，不依赖图形表情单独传达操作。

### 5.4 响应式

- 采用单列移动优先布局；棋盘为 `min(92vw, 58dvh, 600px)` 的正方形，Canvas 内部按 CSS 尺寸与 `devicePixelRatio` 调整像素密度，保持 20×20 等宽等高、不变形。
- 页面使用 `box-sizing: border-box`、`overflow-x: hidden`、`max-width: 100%`；主要控件位于棋盘下方或页头，不覆盖棋盘。
- 低高度横屏切换为「棋盘 + 控件」双列布局，避免四向按钮挤出视口。
- 使用 `env(safe-area-inset-*)`；`100dvh` 带 `100vh` 回退；375×667、390×844、768×1024、1440×900 下检查无横向滚动及明显遮挡。

## 6. 接口影响

- 无外部 API、后端、数据库、CDN 或第三方脚本；不新增跨系统接口。
- 唯一持久化接口是浏览器 localStorage 的单个整数键，属于本地、可清除的体验数据，不含个人信息。
- 仓库基线为空，无既有模块、路由、样式或兼容负担；实现为新增静态文件，不迁移现有代码。
- 运行方法固定为静态服务器；不使用打包器或环境变量。README 将给出 `python3 -m http.server`、浏览器地址和测试命令。

## 7. 主要风险与缓解

| 风险 | 缓解 |
| --- | --- |
| rAF 抖动导致速度变化或补步 | 固定步长 accumulator；单帧最多一步；开始/继续/隐藏时重置时间基准 |
| 快速连按造成反向或回环 | 单槽待转方向；先与当前方向做反向校验；每步只消费一次 |
| 尾格碰撞误判 | 未进食时自撞集合排除当前尾格；进食时保留尾格；测试覆盖两分支 |
| localStorage 抛错阻断启动 | 读写均捕获异常，内存值兜底；游戏状态不依赖存储成功 |
| 小屏棋盘或按钮被遮挡 | 棋盘尺寸同时受视口宽高约束；44px 以上按钮；横屏双列；按指定视口实测 |
| 覆盖层隐藏后焦点丢失 | 统一状态渲染；显式移交和恢复焦点；背景设置 `inert` 或降级隔离 |
| Canvas 在高分屏模糊 | backing store 随 CSS 尺寸和 DPR 更新，逻辑坐标始终为 20×20 |
| 为流程测试扩大范围 | 音效、滑动、PWA、跨浏览器性能矩阵均不实现；未执行项如实记「未验证」 |

## 8. 验证计划

### 8.1 自动逻辑测试

在 `testvb/` 运行：

```bash
npm test
```

`package.json` 将脚本指向 `node --test tests/*.test.js`，测试至少包括：

1. 向右时合法转为向上；向右时向左被拒绝，方向仍为右。
2. 每步只消费一次转向，被拒绝的反向不会在后续步生效。
3. 食物置于前方时，`step()` 后得分 0→10、蛇长 3→4、食物不与蛇重叠、步长 150→144ms。
4. 连续三食物后步长为 132ms；达到下限后保持 70ms。
5. 蛇头越过右边界后状态为 `gameover`，得分不变。
6. 构造蛇转向进入自身非尾格时结束；未进食进入即将离开的尾格时不算碰撞。
7. `restart()` 后蛇长 3、得分 0、方向向右、步长 150ms，并处于可继续游戏的 `running`。
8. `classifyRecord` 覆盖新纪录、正分追平、低分、首次 0/0 四个分支。

测试节点必须保存实际命令、退出码与关键输出；任何失败如实保留，不根据文档推断通过。

### 8.2 静态冒烟

```bash
cd testvb
python3 -m http.server 8000 --bind 127.0.0.1
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/
```

期望状态码 `200`。如检查浏览器控制台，记录实际 error 与未处理 rejection；不宣称未执行的检查通过。

### 8.3 浏览器人工/自动化检查

- 依次验证 `idle → running → paused → running → gameover → running`，开始后焦点离开隐藏按钮。
- 使用方向键、WASD 和四向按钮操作；确认反向被拒、页面不滚动、仅键盘可完成闭环。
- 在 375×667、390×844、768×1024、1440×900 视口检查棋盘完整、控件不遮挡、无横向滚动；手机触控模拟检查按钮热区。
- 正常获得最高分后刷新确认持久化；通过覆盖/禁用 localStorage 模拟抛错，确认游戏仍能完整结束且无未捕获异常。
- 对局中切后台至少 2 秒再返回，确认 `paused`、蛇未移动、继续后等待完整步长。
- 检查控制台无 error；检查 `aria-live` 文本、焦点顺序和基本对比度。

### 8.4 证据边界

- 本轮主验收为静态服务器加当前可用桌面 Chrome/Chromium；真实 iOS/Android、Safari、Firefox、读屏软件、60fps/低端设备、首屏 1.5s、10/30 分钟稳定性与断网刷新若未执行，均记录「未验证」。
- 自动测试通过只证明核心逻辑分支；响应式、焦点、控制台和存储降级仍需对应实测证据。
- 本测试止于本地交付闭环，不推送远端、不创建 PR；人工门禁保留。
